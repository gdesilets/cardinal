# Premium Journals v2.7 migration boundary

v2.7 is a future-only, disabled pilot. Canonicals are reserved for `raw/channel_segments_v2_7`; immutable navigation sources are confined to `raw/premium_journals_v2_7_checkpoints/<day>/page_NNN`. v2.6 remains the only live and historical authority. No Jan 1–7 canonical, checkpoint, schedule binding, or Questions artifact is modified or reinterpreted.

For each exact forum group, v2.7 first tries a direct proof made only from row-owned reply permalinks and/or exact, uploaded message-accessory attachments. It records every candidate tuple, the current parent-forum source URL, and immutable page-plan byte/hash bindings. It must resolve exactly one non-parent child and all available candidate families must agree. Any malformed, conflicting, or incomplete signal falls back to ordinary v2.6 group-header navigation.

Each direct proof gets its own exclusive, immutable checkpoint. Retry and resume read that checkpoint before creating new timestamped evidence, validate it against the current group and exact page-plan bytes, and reuse its original evidence timestamp. Unreadable, tampered, or semantically drifted checkpoints fail as immutable conflicts; operators do not delete them to force progress. A page remains unaccepted until its full row/group partition exactly matches the immutable page plan and every planned group has either a valid v2.7 direct checkpoint or a fully validated v2.6 header checkpoint. Header fallback revalidates source, back URL, query, page, membership, full-page hash, and exact on-disk checkpoint bytes. There is no title cache, inferred thread ID, attachment download, external source, or cross-day child reuse.

The caller must supply the validated active v2.6 schedule; omission fails the no-double-authority result. Canonical integration also requires the exact integer page sequence implied by the positive reported total.

The current integration is deliberately `shadow_only_non_promotable`. It audits route → adapter → canonical fields and rejects overlapping v2.6 authority, but always returns `promotion_allowed: false`. Enablement requires a separate reviewed migration that removes the same day from v2.6 authority, changes the disabled route grammar, and passes the generic v2.7 QA over canonical totals, terminal state, exact maps/partition, every source byte/hash, and reply/attachment summaries.
